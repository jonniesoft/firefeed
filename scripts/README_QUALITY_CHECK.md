# Скрипт проверки качества кода

Автоматизированный скрипт для проверки качества кода в проекте FireFeed с генерацией подробных отчетов.

## 📋 Описание

Скрипт `run_quality_check.sh` запускает все основные инструменты проверки качества кода и создает структурированные отчеты в папке `report/`.

## 🚀 Использование

### Базовый запуск
```bash
./scripts/run_quality_check.sh
```

### Запуск конкретных инструментов
```bash
# Только linting и типизация
./scripts/run_quality_check.sh --tools ruff,pyrefly

# Все инструменты кроме pytest (для быстрой проверки)
./scripts/run_quality_check.sh --tools ruff,pyrefly,usort

# Только тесты
./scripts/run_quality_check.sh --tools pytest
```

### Другой каталог для отчетов
```bash
./scripts/run_quality_check.sh --output-dir /tmp/my_reports
```

## 📊 Инструменты

Скрипт поддерживает следующие инструменты:

| Инструмент | Назначение | Отчет |
|-----------|------------|-------|
| **ruff** | Проверка кода на соответствие стандартам PEP8, поиск ошибок | `ruff_YYYYMMDD_HHMMSS.txt` |
| **pyrefly** | Проверка типов, статический анализ | `pyrefly_YYYYMMDD_HHMMSS.txt` |
| **pytest** | Запуск тестов, проверка работоспособности | `pytest_YYYYMMDD_HHMMSS.txt` |
| **usort** | Сортировка и упорядочивание импортов | `usort_YYYYMMDD_HHMMSS.txt` |

## 📁 Структура отчетов

```
report/
├── ruff_YYYYMMDD_HHMMSS.txt      # Отчет Ruff
├── pyrefly_YYYYMMDD_HHMMSS.txt   # Отчет Pyrefly
├── pytest_YYYYMMDD_HHMMSS.txt    # Отчет Pytest
├── usort_YYYYMMDD_HHMMSS.txt     # Отчет Usort
└── summary_YYYYMMDD_HHMMSS.txt   # Итоговый отчет
```

## 📄 Содержимое отчетов

Каждый отчет содержит:
- Дату и время проверки
- Выполненную команду
- Полный вывод инструмента
- Анализ результатов
- Количество найденных ошибок

### Пример отчета Ruff

```
================================================================================
Ruff - Отчет о проверке
Дата и время: 2025-11-15 10:30:00
================================================================================

Команда: uv run ruff check . --statistics

================================================================================
ВЫВОД:
================================================================================

All checks passed!
Bytecode compiled 13523 files in 506ms

================================================================================
Конец отчета
================================================================================
```

- Процент успеха
- Список инструментов, требующих внимания
- Ссылки на детальные отчеты

## 🎨 Цветовая индикация

Скрипт использует цветовое кодирование для быстрой оценки результатов:
- 🟢 **Зеленый** - Успешная проверка, ошибок не найдено
- 🔴 **Красный** - Обнаружены ошибки, требуется внимание
- 🔵 **Синий** - Информационные сообщения
- 🟡 **Желтый** - Предупреждения

## ⚡ Интеграция в CI/CD

Скрипт можно использовать в GitHub Actions:

```yaml
- name: Run quality checks
  run: ./scripts/run_quality_check.sh --tools ruff,pyrefly,usort

- name: Upload reports
  uses: actions/upload-artifact@v3
  if: always()
  with:
    name: quality-reports
    path: report/
```

## 📈 Интерпретация результатов

### Ruff
- ✅ Все проверки пройдены - код соответствует стандартам
- ❌ Найдены ошибки - требуется исправление

### Pyrefly
- ✅ 0 ошибок - типизация корректна
- ❌ Ошибки типов - добавить аннотации или `# type: ignore`

### Pytest
- ✅ Все тесты прошли - код работает корректно
- ⚠️ Часть тестов не прошла - требуется исправление

### Usort
- ✅ Импорты корректно отсортированы
- ❌ Есть проблемы с импортами

## 🚨 Часто встречающиеся проблемы

### Ruff: ARG001 (Unused function argument)
**Проблема**: Параметры функций не используются
**Решение**: Переименовать в `_param` или добавить `# noqa: ARG001`

### Pyrefly: Unbound name
**Проблема**: Переменная может быть не инициализирована
**Решение**: Добавить инициализацию или `# type: ignore`

### Pytest: Failed
**Проблема**: Тесты не проходят
**Решение**: Исправить логику или моки в тестах

## 💡 Рекомендации

1. **Запускайте проверки регулярно** - после каждого изменения
2. **Проверяйте итоговый отчет** - для быстрого обзора
3. **Изучайте детальные отчеты** - для понимания проблем
4. **Исправляйте проблемы сразу** - чем раньше, тем лучше
5. **Используйте в CI/CD** - автоматическая проверка при коммитах
